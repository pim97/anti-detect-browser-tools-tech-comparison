## Evidence tiers

| Tier | Definition | Established by |
|:----:|-----------|----------------|
| **A** | Verified in source at a stated commit | Reading the code in an isolated container; file paths cited |
| **B** | Vendor-reported, not reproduced here | The project's README, release notes, or docs |
| **C** | Community-reported | Issue trackers, forums, third-party posts |
| **D** | Not established | No evidence located in either direction |

Two constraints follow from the method (see [METHODOLOGY.md](METHODOLOGY.md#what-we-did-not-do)):

1. **No claim about anti-bot service outcomes in this repository exceeds Tier B.** No
   head-to-head benchmark against Cloudflare, DataDome, Kasada, Akamai, PerimeterX, or
   Imperva was run.
2. **Vendor-published benchmarks remain Tier B** regardless of detail. They record what
   the vendor observed on the vendor's configuration.

> [!NOTE]
> **Tier D means nobody published a test — not that the tool failed one.** Collapsing
> "not established" into "does not implement" is the most common way a comparison
> misleads, so the two are never merged here.

### Changes since the 2026-08-14 revision

Eight of ten tools published releases. Material changes to previously documented behaviour:

- **Camoufox** moved to a Firefox 156.0.1 base (pre-release line `v156.0.1-beta.33`; 44
  patches, was 34). At repository HEAD, fpgen replaces BrowserForge as the fingerprint
  generator (PyPI 0.5.6 still uses BrowserForge), the cursor path is a replay of
  recorded movements generated in Juggler JS rather than a C++ generator, and canvas
  output is not perturbed.
- **invisible_playwright** (0.7.0 to 0.25.7): the wrapper now vendors a modified copy of
  Playwright's Python client and an in-process Python Juggler server, so "unmodified
  Playwright client" no longer holds. The `invisible_firefox` repository was deleted on
  2026-08-18. The launch ping is still on by default; it is now disclosed in the
  wrapper's CHANGELOG and shown as a badge, but not in the wrapper README text or docs.
- **Clearcote**'s open build moved to Chromium 150 with 37 patches (was 149 and 32); the
  SDKs went from 0.26.1 to 0.33.0 and the SDK list now includes .NET; the project README
  describes a free-with-GitHub tier and hosted browsers (**Tier B**).
- **CloakBrowser**'s Pro binary moved to Chromium 152 with 87 claimed patches (was 150
  and 71); a free GitHub-sign-in key tier receives the latest build. The sandbox finding
  is unchanged.
- **Obscura** v0.2.0 to v0.2.3: CDP and MCP endpoints refuse a non-loopback bind without
  a token (v0.2.3); a tenth workspace crate (`obscura-ssrf`); the render engine is
  69,866 lines.
- **Patchright** 1.61.x to 1.63.0: in the current source, init scripts are registered only
  through CDP `Page.addScriptToEvaluateOnNewDocument`; the project README still
  describes route-based injection (source read, not run). Scrapling's browser tier
  inherits this.
- **Scrapling** 0.4.15 (MCP tools 10 to 13; the HTTP transport requires a token) and
  **SeleniumBase** 4.54.13 (in-tree MCP server; the UC Mode code is unchanged).
- **Code metrics** were regenerated with a corrected `scripts/codemetrics.py` (five
  measurement defects fixed), so several earlier figures are not comparable; see
  [CODE-REVIEW.md](CODE-REVIEW.md#how-the-numbers-were-produced).

### Notes on reading these tables

- **Patch counts measure surface area touched, not quality.** Projects split changes at
  different granularities; 87 patches and 37 patches are not comparable quantities.
- **"Delegates" describes a dependency relationship, not a deficiency.** Scrapling's
  browser-tier evasion is Patchright's implementation, so Scrapling inherits Patchright's
  properties and limits in that tier.
- **Absence of TLS impersonation is expected for real-browser tools.** A real browser
  produces a real browser's TLS signature. The row is decision-relevant only for
  HTTP-only request paths.
- **Two cells changed direction during verification** on 2026-08-14: SeleniumBase and
  CloakBrowser `Runtime.enable` were previously stated as handled, in both the July 2026
  revision and an earlier draft of this one. Neither is supported by locatable evidence.
- **Several cells were corrected on 2026-09-30 for claims that were already inaccurate at
  the 2026-08-14 commits**: Obscura WebGL and canvas, Camoufox canvas noise and its
  `Runtime.enable` test reference, invisible_playwright's "unmodified Playwright client",
  and Clearcote's network-stack statement (patch `210-tls-network-persona`). They are
  itemised in [CHANGELOG.md](CHANGELOG.md).

## Lineage — ten tools, fewer independent implementations

Several of these depend on each other. Selecting two for redundancy can mean selecting
the same implementation twice: if that lineage is fingerprinted, both fail together.
Every edge below was verified in source (**Tier A**).

```mermaid
graph LR
  subgraph FF["Firefox lineage"]
    direction LR
    Firefox["Firefox 156.0.1"] --> Camoufox
    FPGen["fpgen<br/><i>fingerprint generator, repo HEAD</i>"] --> Camoufox
    Firefox151["Firefox 151"] --> FAP["firefox_antidetect_patch<br/><i>public fork, 104 files</i>"]
    FAP --> InvisiblePW["invisible_playwright"]
    PWClient["Playwright Python client<br/><i>vendored, modified</i>"] --> InvisiblePW
  end

  subgraph CR["Chromium fork lineage"]
    direction LR
    Chromium --> CloakBrowser["CloakBrowser<br/><i>closed binary</i>"]
    Chromium --> UG["ungoogled-chromium"] --> Clearcote
  end

  subgraph PW["Playwright-patch lineage"]
    direction LR
    Playwright --> Patchright --> Scrapling
    CDPPatches["CDP-Patches<br/><i>input</i>"] -.pairs with.-> Patchright
    Playwright --> Rebrowser["rebrowser-patches"]
    Rebrowser --> TB["turnstilebrowser-<br/>playwright-core 1.49"] --> XDriver
    Rebrowser --> RPC["rebrowser-playwright-core"] --> BotaJS["Botasaurus JS driver"]
  end

  subgraph CDP["Raw-CDP lineage"]
    direction LR
    NoDriver -.derived.-> SeleniumBase["SeleniumBase<br/><i>CDP Mode</i>"]
    Botasaurus["Botasaurus<br/><i>own CDP driver</i>"]
  end

  subgraph OWN["Independent engine"]
    direction LR
    V8["V8 / deno_core"] --> Obscura
    H5["html5ever"] --> Obscura
  end
```

What this shows:

- **Scrapling's browser tier *is* Patchright** (`patchright>=1.62.1`; the latest Patchright is
  1.63.0). Choosing both is choosing one implementation.
- **SeleniumBase's CDP Mode is NoDriver-derived** — stated in the file headers of
  `undetected/cdp_driver/cdp_util.py` and `browser.py`.
- **XDriver and Botasaurus's JS driver both descend from rebrowser-patches**
  (`turnstilebrowser-playwright-core` 1.49.0; `rebrowser-playwright-core` ^1.49.1).
- **Clearcote's `CREDITS.md` names two upstream projects** — `fingerprint-chromium` as the
  base of its engine-level controls and `chromiumfish` for its agent layer (a vendor
  statement, **Tier B**; not drawn as edges above). It remains independent of the
  Playwright-patch family.
- **Camoufox, Obscura, Clearcote and CloakBrowser are genuinely independent** of the
  Playwright-patch family. Clearcote and CloakBrowser are Chromium-derived, Camoufox is
  Firefox-derived, and Obscura is a from-scratch engine.
- **invisible_playwright is a second, independent Firefox lineage** — its own C++ fork,
  driven through a vendored, modified copy of Playwright's Python client and an
  in-process Python Juggler server; the Playwright API shape is kept without a bespoke
  launcher API.

## Code quality

Detection capability and code quality are independent properties. Full analysis —
size, typing, tests, error handling, dependency hygiene, security patterns, with
per-file citations — is in **[CODE-REVIEW.md](CODE-REVIEW.md)**. Metrics are reproducible
via `scripts/codemetrics.py`.

Findings that bear on a build decision:

| Finding | Detail |
|---------|--------|
| **CloakBrowser disables the Chromium sandbox by default, and Playwright's `chromium_sandbox=True` cannot restore it** | `--no-sandbox` is part of the wrapper's default arguments (`config.py:54-76`, literal at `:64`; the Node and .NET wrappers and `cloakserve` do the same). Playwright itself adds the flag unless `chromiumSandbox` is true, but the wrapper adds it as well, so that switch has no effect under the default arguments. The argument merge can add and override flags but cannot remove them; the only opt-out is `stealth_args=False`, which also drops the wrapper's fingerprint seed and platform flags (the README shows re-adding `--fingerprint` by hand, `README.md:818-821`). Combined with a closed binary, this means unauditable native code processing hostile input with no OS sandbox. The README does not mention the flag; the CHANGELOG does. |
| **XDriver ships a frozen bundle with no drift detection** | A prebuilt `playwright-core` 1.49.0 fork, 295 lines of first-party Python, zero tests. Nothing detects that upstream has moved. |
| **Patchright handles a fragile approach well** | AST patching that fails loudly (222 `…OrThrow(` calls across `driver_patches/`) plus `check_patch_impact.yml`, which diffs Playwright versions and writes an impact report; in the release workflow a failed test run opens an issue and a draft PR. |
| **SeleniumBase is large and largely untyped** | 102,228 production lines; `base_case.py` is 17,702 lines and 579 methods in one class; 3.4% of functions carry any annotation; 515 broad `except` handlers; 550 sleep calls. Forking or debugging it is correspondingly expensive. Its 42 `shell=True` calls include 12 in `core/` launch helpers. |
| **Obscura's panic containment is partial** | 91 matching lines of non-test `.unwrap()` and 1 `panic!` across 168,827 production lines (inline `#[cfg(test)]` modules stripped; the earlier 2,326 figure included test code). Release builds use `panic = "unwind"`, each CDP connection runs on its own OS thread, and `catch_unwind` guards the JS-op, URL-op, module-evaluation and resource-load boundaries. Stack overflows, allocation failures and V8 fatal errors still abort the process. Relevant if you run `obscura serve` as a long-lived service. |
| **Botasaurus swallows errors** | 38 bare `except:` clauses; `botasaurus-driver` has zero test files across 50,169 lines; PyPI (4.0.101) is ahead of the published source (4.0.92). |
| **Scrapling pairs high typing coverage with a low smell count** | 85.5% annotation coverage, 60.4% docstrings, 0 bare excepts, 7 broad excepts across 16,219 lines, 63 test files, the only pre-commit config of the ten. |

| Fingerprint spoofing not observable as JS property-descriptor modification | Camoufox, CloakBrowser, Clearcote, invisible_playwright | Values substituted in C++ before JS can inspect them |
| Statistically distributed fingerprint rotation | Camoufox | fpgen-generated profiles with coherence rules (repo HEAD; PyPI 0.5.6 uses BrowserForge) |
| Import and present a specific captured device fingerprint | Clearcote | `--fingerprint-profile` with a bundled verifier (Camoufox ships opt-in real presets instead, `fingerprint_preset=True`) |
| Unmodified Playwright API surface | Patchright, CloakBrowser, Clearcote | Drop-in driver or SDK |
| `Runtime.enable` tell addressed | Patchright, Clearcote, Camoufox (not applicable — Juggler) | Isolated contexts; C++ patch; non-CDP protocol |
| TLS/JA3 impersonation on HTTP requests | Scrapling, Obscura (build-gated) | `curl_cffi`; `wreq` |
| Mouse-motion model for input | Botasaurus, CloakBrowser, Clearcote, Camoufox, invisible_playwright | Bézier trajectories; C++ humanized input plus SDK paths; recorded-movement replay in Juggler JS; client-side seeded path planner |
| CAPTCHA handling in-framework | SeleniumBase, Scrapling (Cloudflare only), Botasaurus (Cloudflare only) | Click-based solving; `solve_cloudflare` |
| HTML parsing without a separate library | Scrapling, Obscura | lxml-based parser; `html5ever` |
| Crawler/spider framework | Scrapling, Botasaurus | Scrapy-like spiders; framework primitives |
| Node.js or .NET client | Patchright, CloakBrowser, Clearcote | Published SDKs |
| Test-framework integration | SeleniumBase | pytest, unittest |
| Rebuildable engine from published sources | Camoufox, Clearcote, Obscura | Patches + build scripts; Rust workspace |
| Signed, checksummed release binaries | Clearcote, CloakBrowser | Clearcote: GPG signature + SHA-256. CloakBrowser: the wrapper verifies a pinned Ed25519 signature over `SHA256SUMS` (the binary itself is closed) |
| Resident memory below a browser's | Scrapling (HTTP tier), Obscura | No browser process; own engine — **Tier B**, vendor figures |
| Firefox rather than Chromium engine | Camoufox, invisible_playwright | Firefox 156.0.1 / 151 forks |
| WebRTC UDP routed through a SOCKS proxy (implemented, off by default) | invisible_playwright | SOCKS5 UDP ASSOCIATE layer added to Necko (+423 lines), gated by `network.proxy.socks_remote_udp` (default false), which `invisible_core` does not set; behind a proxy the core blocks direct UDP and declares a server-reflexive candidate from the exit IP. Clearcote's SDK has a `socks5Udp` option whose engine side is not in the public tree |
| Playwright API shape without a bespoke launcher API | invisible_playwright | Engine carries Juggler; the Python client is a vendored, modified copy |

Requirements with no tool in this set: macOS Clearcote builds, WebGL in Obscura
(`getContext('webgl')` returns `null`), first-party handling of Akamai/DataDome/Kasada/Imperva
in any of the ten.

## Detection layers and which tools address them

Layer taxonomy with the tools whose source addresses each, per the architecture tables.

```
Layer 1 — Automation protocol tells
  Runtime.enable / execution contexts .... Patchright, Clearcote
  Non-CDP automation protocol ............ Camoufox (Juggler)
  ChromeDriver binary markers ............ SeleniumBase (cdc_ removal)
  CDP input characteristics .............. CloakBrowser (Tier B), Clearcote

Layer 2 — Browser fingerprinting
  navigator.webdriver .................... all ten
  Canvas / WebGL ......................... Camoufox (WebGL only; canvas is not
                                           perturbed), CloakBrowser (Tier B), Clearcote
  Screen / window geometry ............... Camoufox, CloakBrowser (Tier B), Clearcote
  AudioContext ........................... Camoufox, CloakBrowser (Tier B), Clearcote
  Font enumeration ....................... Camoufox, CloakBrowser (Tier B), Clearcote

Layer 3 — Behavioural signals
  Mouse-motion model ..................... Botasaurus, CloakBrowser, Clearcote, Camoufox,
                                           invisible_playwright
  Click and keystroke timing ............. Botasaurus, SeleniumBase, CloakBrowser
  Navigation patterns .................... not addressed by any tool; a property of
                                           calling code, not the driver

Layer 4 — Network
  TLS fingerprint (JA3/JA4) .............. Scrapling (HTTP tier), Obscura (build-gated)
  WebRTC / UDP leakage ................... Camoufox, Clearcote
  IP reputation .......................... not addressed by any tool
  DNS leakage ............................ not addressed by any tool

Layer 5 — Layout and rendering probes
  getBoundingClientRect .................. all real-browser tools; Obscura in
                                           render-enabled builds only
  getComputedStyle ....................... all real-browser tools; Obscura in
                                           render-enabled builds only
  Canvas/WebGL pixel output .............. all real-browser tools; Clearcote can forward
                                           canvas operations to real GPU hardware
```

Layers 3 (navigation patterns), 4 (IP reputation, DNS), and any account-history signal
are outside what a browser-automation library controls. They are properties of
infrastructure and calling code.

## Variables affecting outcomes

The previous revision published a table of success-rate percentages by protection tier
(«90%+», «60-80%», «20-40%», «<20%»). No study, target list, sample size, or date was
attached to those figures, and they have been removed rather than revised.

What can be stated without a benchmark is which variables the tool layer does and does
not control:

| Variable | Controlled by the tools compared here? |
|----------|----------------------------------------|
| Browser fingerprint surface | Yes — the primary function of Camoufox, CloakBrowser, Clearcote |
| Automation protocol tells | Yes — Patchright, Clearcote, SeleniumBase, Camoufox |
| Input event characteristics | Partially — five tools implement a motion model |
| TLS fingerprint | Only on HTTP-only paths (Scrapling, Obscura) |
| IP address reputation | **No** — supplied by your proxy provider |
| Request volume, timing, and path order | **No** — a property of your calling code |
| Account age and session history | **No** — outside the browser layer |
| Target's protection tier and configuration | **No** — and vendor claims rarely state which tier was tested |
| Durability over time | **No** — detection is adversarial; a passing result is scoped to that target on that date |

Consequence for evaluating any claim, in this repository or elsewhere: a stated pass
rate without the IP type, target list, protection tier, trial count, and date is
underspecified, because the unstated variables include ones the tool does not control.

## Reproducing this report

Version and health data:

```bash
python scripts/verify.py --write
```

Source verification. The ten projects are unaudited third-party code, including patched
browser binaries; they are cloned into a container and never onto a workstation:

```bash
./scripts/sandbox.sh up        # clone into a Docker volume, then disconnect the network
./scripts/sandbox.sh sh        # offline shell for reading source
./scripts/sandbox.sh nuke      # destroy container and volume
```

The container runs with `--cap-drop=ALL`, `--security-opt=no-new-privileges`, a
read-only root filesystem, and no network after cloning completes. No dependency
installation, build, test run, or binary execution is performed at any point in
producing this report; Tier A means the code was read, not run. Details:
[METHODOLOGY.md § Source handling](METHODOLOGY.md#source-handling).
